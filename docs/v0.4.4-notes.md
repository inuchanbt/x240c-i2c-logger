# X240C PicoXTools Direct Logger v0.4.4

v0.4.4 fixes the remaining phase-aware SET boundary found during the large
PPS sweep.

## Fixed edge case

The real capture contained:

    14:36:20.125  S 6C W 04 1B 06 P
                  -> 48.000 V

    14:36:21.447  S 6C W 06 3D Sr 6C W 04 D3 02 P
                  -> phase 0: current ~5.050 A
                  -> phase 1: next voltage 15.000 V

The 48 V SET had already moved from `base` to `pending` because more than
300 ms had elapsed.

v0.4.3 correctly split the repeated-START transaction into two logical
operations, but when phase 1 (15 V) arrived it closed the old SET before
committing phase 0 from `pending_recent`.

Result in v0.4.3:

    36 V -> 48 V
    current missing

v0.4.4 checks `_agg_parent_tx_id` before closing a SET. If pending logical
phases belong to the same physical transaction as the incoming new voltage,
those earlier phases are committed to the old SET first.

Expected v0.4.4 result:

    36 V -> 48 V
    current = 5.050 A
    transaction_count = 2
    operation_count = 2

while the same physical repeated-START transaction also starts the next 15 V
SET from its voltage phase.

## Preserved behavior

- transaction CSV stays physical-transaction based
- SET aggregation remains phase-aware
- write-data NACK flagging remains enabled
- READ final-byte NACK is still treated as normal
- semantic 5 V tail window remains 5000 ms
- PPS/AVS voltage decoding is unchanged
